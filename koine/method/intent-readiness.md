# Intent readiness

Readiness is a loop, not a gate. It says what can be built now and on what fallbacks; it never blocks a use case as a whole, and it never refuses work on the strength of how a fact was obtained.

## The loop

1. **Read the artefacts.** Take what the team already has and read it with base tools, following [artefact-first intake](artefact-first-intake.md).
2. **Record the facts.** Write each value into the intake record with its artefact identity, its position inside that artefact, its extractor and a status of extracted, inferred or confirmed. Put the whole pass of inferences to a human as one bulk confirmation.
3. **Recompute readiness per segment.** A segment runs from its sources to the next checkpoint or target output. Each segment is judged on the facts that segment needs, so one absent input never stops the rest.
4. **Show the three lists.** What is buildable now and on which fallbacks, including any labelled synthetic fill. The gaps, each with a suggested owner and whether synthetic data can fill it. The open questions, which are the residual questions no artefact answered.
5. **Ask the residual questions.** Only those. An answer of "I do not know yet" is a first-class answer that creates a gap.
6. **Repeat.** The human decides what to obtain, what to synthesise and what to leave. Accepted gap work becomes tracked items. A use case already in build re-enters the loop when a new output or scenario appears, and that starts a new version.

## What readiness does not do

It suggests and labels; it never enforces. Synthetic data is labelled progress and is never silently equated with real-data parity. A standing condition that was never answered records the default it falls back to, so nothing is applied that the record does not show. Nothing here refuses work because a fact was inferred rather than confirmed.
